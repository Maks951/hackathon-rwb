# Применение пяти регламентов

Версия 0.1, 31.10.2026. Статус: в работе. Согласование не заявляется.

## Правила системного анализа
platform-spec.md описывает назначение, границы, историю, ответственных, статусы согласования, терминологию, сценарии, frontend/backend, данные, интеграции, требования и приемку. platform-flow.mmd содержит диаграмму. Корпоративные Jira/Confluence/Figma ссылки, подписи, SLA и ИБ-согласования отсутствуют и отмечены как открытые пункты.

## Шаблон ТЗ
Требования и критерии приемки заданы в platform-spec.md; фактические проверки отделены от целевого поведения. Нагрузочные показатели не придуманы. Генерируемый продукт должен содержать собственное ТЗ из своих требований, а не копию документа платформы.

## Шаблон API
platform-api.md содержит основные методы, параметры, примеры, ошибки, таблицы и алгоритмы. contracts/platform-openapi.json переэкспортирован из объединенных routes, включая artifacts. Дополнение ниже фиксирует новые методы. Авторизация пока отсутствует; нельзя заявлять 401/JWT как реализованные.

## Шаблон ADR
adr-platform-runtime.md содержит контекст, статус, альтернативы, плюсы/минусы, решение, последствия и ответственных. Выбор DB queue сохраняет принятую архитектуру. Это не означает внешнего утверждения организаторами.

## Шаблон описания сервисов
platform-service.md и local-stack.md описывают сервисы, ссылки, ограничения, конфигурацию, сборку, запуск, мониторинг и доступ. Корпоративные Zabbix/Grafana/Elasticsearch/Kibana, /metrics и трехуровневый health не подключены. Текущий /health возвращает ok/not_ready. Удаленный endpoint перезапуска не реализован. Эти расхождения требуют решения команды, не считаются выполненными.

## Передача требований модели
app/resources/documentation-policy.json содержит список документов и секций; pipeline передает policy и SHA256 в каждый stage, проверяет документы перед package. Это структурная проверка; смысловое соответствие всей документации автоматически не доказано.

## Дополнение API: артефакты
GET /api/v1/runs/{run_id}/artifacts. Назначение: список сохраненных файлов запуска. Вход: UUID run_id в path, тела и query нет. Доступ: закрытая demo, встроенной авторизации нет. Успех 200: {items:[{id,run_id,step_id,path,mime_type,size_bytes,sha256,created_at}]}; точный состав и типы в OpenAPI. Ошибки: 400 неверный UUID, 404 run отсутствует, 503 ошибка БД. Таблицы: runs, artifacts. Алгоритм: проверить run, получить файлы, отсортировать по path. Внешних вызовов нет.
GET /api/v1/artifacts/{artifact_id}/content. Вход: UUID artifact_id, без тела. Успех 200: UTF-8 текст или JSON, X-Content-Type-Options: nosniff, Cache-Control: no-store. Ошибки: 404, 413 более 1 MiB, 409 путь/hash поврежден, 400 не UTF-8. Таблица: artifacts. Проверяются принадлежность, безопасный путь, размер и SHA256; HTML возвращается text/plain. Пример: GET /api/v1/artifacts/00000000-0000-0000-0000-000000000001/content; для отсутствующего ID ожидается 404, пример не является выполненным запросом.
